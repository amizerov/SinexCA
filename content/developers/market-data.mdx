Биржевые API отличаются форматами символов, временными метками, наборами интервалов и доступными показателями. Sinex приводит ответы к общей внутренней модели, сохраняя источник каждого рынка.

## REST и WebSocket

REST используется для каталога, истории свечей, начальных снимков и резервного обновления. WebSocket передаёт изменения выбранного инструмента с меньшей задержкой. При смене пары старая подписка закрывается до запуска новой.

## Нормализация

Адаптер преобразует внешний символ в базовый и котируемый актив, числа — в конечные числовые значения, а время — в Unix timestamp. Некорректные и неполные ответы проходят проверку до передачи интерфейсу.

## Неизвестные показатели

Если источник не передаёт точный объём в валюте котировки, Sinex не выдаёт базовый объём за USDT-оборот. Допустимая оценка помечается символом `≈` и поясняется в интерфейсе. Неизвестное значение остаётся пустым.

## Данные для дневного VWAP

`Candle.volume` — количество базового актива. Веса VWAP не берутся из 24-часового оборота или котируемой валюты. Проверены следующие поля REST-нормализаторов; те же соглашения используются существующими candle WebSocket-декодерами:

| Адаптер Spot | Источник базового объёма свечи |
| --- | --- |
| Binance, Bybit, OKX, Bitget, MEXC, BingX | Элемент 5 массива OHLCV |
| Gate | Элемент 6; элемент 1 — оборот в котируемой валюте |
| Kraken | Элемент 6; элемент 5 — биржевой VWAP |
| Coinbase | Элемент 5 |
| KuCoin, Bitfinex, WhiteBIT | Элемент 5 после перестановки OCHL в OHLC |
| HTX | `amount`; `vol` — оборот в котируемой валюте |
| Crypto.com | `v` |

`/api/market/vwap-history` догружает текущую сессию с 00:00 UTC через существующие адаптеры. Необязательный `endTime` задаётся в Unix-секундах и преобразуется внутри адаптера в его нативную единицу. Ключ кэша учитывает конечную дату. Пагинация последовательная и ограниченная; ответ с неполной сессией не используется для построения VWAP. Серверный кэш объединяет одинаковые текущие запросы. При включённом VWAP потоковая история хранится в памяти до размера суток плюс обычный буфер; свечи в пользовательские настройки не записываются.

У Kraken OHLC REST доступно не более 720 последних свечей, поэтому для 1m во второй половине суток начало сессии может быть недоступно. HTX возвращает до 2000 последних свечей, достаточных для суток на его минимальном интервале 1m. Источники: [Kraken OHLC](https://docs.kraken.com/api-reference/market-data/get-ohlc-data), [HTX Spot Market](https://github.com/htx-exchange/htx-skills-hub/blob/main/skills/htx/spot-market/SKILL.md), [Bybit Kline](https://bybit-exchange.github.io/docs/v5/market/kline).

При пропусках используется консервативное поведение: сессия не рисуется, даже если причина разрыва — отсутствие сделок. Короткие исторические страницы 1h проверены живыми запросами для всех 14 адаптеров; ограничение исторической конечной даты соблюдается у 12, HTX и Kraken используют последние доступные свечи. Длительная загрузка секундных сессий и все комбинации биржа/таймфрейм живыми запросами не проверялись.

## Свежесть

Время получения и известное время источника используются для выявления устаревших данных. Старый стакан не должен участвовать в учебном исполнении заявок.
