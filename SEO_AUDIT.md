# SEO-аудит Sinex

Проверка: 12 ноября 2026 года. Изменения выполнены локально, без публикации на sinex.argoai.ru.

## Найденные проблемы

- В Яндексе на предоставленном скриншоте остались «Sinex broker» и описание только Binance. Прямой HTTP-запрос уже показывает более новую версию сайта, но её заголовок и описание также отличались от запрошенных.
- Заголовки `/help` и `/blog` повторяли бренд: «Справка Sinex — Sinex», «Блог Sinex — Sinex».
- Twitter title/description наследовались от главной на других страницах. На `/about` наследовались также Open Graph title, description и URL главной.
- Не было JSON-LD WebSite. На страницах разделов и `/about` отсутствовали BreadcrumbList; крошки статей не начинались с главной.
- `/about` не имела входящих ссылок в проверенных публичных страницах. Главная ссылалась из разделов сайта только на справку.
- Отдельная PNG-версия `/icon.png` отсутствовала (HTTP 404). ICO, SVG и Apple PNG уже существовали и отвечали HTTP 200.
- Sitemap сообщал время каждой сборки как дату изменения главной; это поле убрано, поскольку реальная дата изменения неизвестна.

Не обнаружены дубликаты обычных title/description между 19 публичными маршрутами до изменений. Они уже были уникальны; исправлены повтор бренда внутри title и наследуемые социальные метаданные. `metadataBase` уже корректно указывала на https://sinex.argoai.ru. Canonical, robots.txt, sitemap.xml и серверный HTML статей уже присутствовали. Разница завершающего слеша у корня сайта не считалась неисправным canonical.

## Границы функциональности

Главная `/` является терминалом. «Рынки» — панель внутри него, а не отдельная страница. `/terminal` и `/markets` отвечают 404; не добавлены в sitemap и навигацию.

По `lib/market/exchange-config.ts` подключены 13 бирж. README прямо указывает, что межбиржевое сравнение и арбитражный сканер ещё не реализованы. Обещание «арбитраж на 15 биржах» не добавлено. До его использования требуется реализовать и проверить соответствующие возможности. Торговая логика, API бирж, WebSocket, существующие сервисы и базы не изменены. Для HTTP-проверки production build использовалась отдельная временная QA-база.

## Что исправлено

- Для главной установлен title и description из задания, для остальных публичных страниц — уникальные метаданные. Существующие уникальные названия и описания 13 статей сохранены из frontmatter MDX; суффикс бренда добавляется только если Sinex ещё нет в названии.
- Единый SEO-helper задаёт canonical, Open Graph и Twitter для каждой страницы; предотвращено наследование текста главной.
- Добавлены WebSite и полные BreadcrumbList, сохранены Article/TechArticle с фактическими заголовками, описаниями и датами статей.
- Общая Organization проекта и publisher убраны: подтверждённые реквизиты организации отсутствуют. В author статей остаётся только указанная на странице редакционная команда «Команда Sinex» как Organization, без выдуманных адресов, контактов или юридических данных.
- В навигацию добавлены ссылки на основные разделы и `/about`, на страницах разделов и статей — видимые хлебные крошки от главной.
- Добавлена PNG 192×192 из существующего фирменного SVG. Существующие SVG, ICO 16/32/48 и Apple PNG 180×180 сохранены без замены логотипа. Next.js подключает файлы иконок автоматически.
- Существующая Open Graph-картинка `/opengraph-image` сохранена и проверена: 1200×630 PNG, HTTP 200. Карточка Twitter изменена на `summary`; несоответствующие унаследованные title/description устранены.

## Проверки

- `npm run build` — успешно, включая TypeScript и статическую генерацию всех 13 статей. Первая попытка выявила устаревший `.next/dev/types` от старых путей страниц; после удаления только этого сгенерированного кэша сборка прошла.
- `node --import tsx --test tests/content.test.ts` — успешно: метаданные MDX и внутренние ссылки.
- `node tests/seo-check.mjs http://127.0.0.1:3012` — 0 ошибок; 19 публичных страниц с HTTP 200, по одному title и description, все значения уникальны.
- Проверены canonical на production-домен, Open Graph/Twitter title/description/URL, отсутствие noindex и X-Robots-Tag noindex на публичных страницах, JSON-LD, входящие внутренние ссылки.
- HTML получен напрямую по HTTP и разобран с отключённым JavaScript: все 13 статей содержат настоящий H1 и текстовые заголовки MDX. Метаданные совпадают для обычного браузера, Googlebot и YandexBot на выборке главной, справки и статьи; полный проход выполнен с Googlebot.
- `sitemap.xml`: HTTP 200, XML, ровно 19 корректных URL, включая все опубликованные MDX. `/account` и `/api/` исключены.
- `robots.txt`: HTTP 200, общедоступные страницы разрешены, ограничения `/api/` и `/account` сохранены; приватная `/account` сохраняет noindex.
- `/favicon.ico`, `/icon.svg`, `/icon.png`, `/apple-icon.png`, `/opengraph-image`: HTTP 200 с типом image/* и непустым содержимым.
- Несуществующие страницы и статьи отвечают HTTP 404.
- В Chromium без JavaScript проверено расположение навигации терминала и справки при ширине 375 и 1440 px. Мобильное меню справки скрывается существующим CSS; доступные ссылки остаются в footer.
- `git diff --check` — без ошибок.

HTTP-аудит опубликованного сайта до изменений: `.qa/seo-production-before.json`. Полный результат проверки новой сборки: `.qa/seo-build.json`. Скриншоты: `.qa/seo-375-terminal.png`, `.qa/seo-375-help.png`, `.qa/seo-1440-terminal.png`, `.qa/seo-1440-help.png`. Каталог `.qa` игнорируется Git.

## Что сделать вручную после публикации

1. Развернуть изменения на production. Локальная сборка сама по себе не обновляет поисковую выдачу.
2. В Яндекс Вебмастере добавить и подтвердить права на https://sinex.argoai.ru, если это ещё не сделано; проверить HTTPS-версию и перенаправление HTTP на неё.
3. В разделе Sitemap передать https://sinex.argoai.ru/sitemap.xml и проверить обработку без ошибок.
4. В «Индексирование → Переобход страниц» отправить главную, `/help`, `/learn`, `/developers`, `/blog`, `/about` и важные статьи. Переобход главной также нужен для обновления favicon.
5. Проверить ответы сервера, robots.txt, исключённые страницы и отчёт о дублирующихся title/description; затем отслеживать повторный обход и индексирование.
6. Проверить быстрые ссылки после переиндексации. Их состав определяет Яндекс автоматически: наличие меню и крошек помогает обнаружить разделы, но не гарантирует их показ.
7. В Google Search Console подтвердить сайт, передать sitemap и запросить индексирование главной и важных страниц через проверку URL.

Не требуется публиковать OAuth-секреты или менять торговые API. Проверочные токены Яндекса/Google не добавлялись: они не предоставлены.

Поисковые системы могут самостоятельно выбирать заголовок и описание в зависимости от запроса; точный вид сниппета и срок обновления не гарантируются.
